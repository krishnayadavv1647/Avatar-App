# admin

Platform admin, across every workspace. The panel's three **Users & Access** tabs live here (the System and Comms tabs have their own folders):

- **Users** - a server-side searchable, filterable (status / plan / source), paged (30) list; **create** an account (same path as sign-up, `source: manual`), **edit** it (profile, status, role, bonus minutes, plan - one save, validated in full before anything is written), **delete** it, and **export** the filtered list as CSV (`users.service.js`; cells starting `= + - @` are neutralised against formula injection).
- **Status** - "suspended" is the block described below; there is no "pending", since nothing here waits on email verification.
- **Admin role** - a platform admin is an email in `ADMIN_EMAILS` (a superuser list that cannot be demoted from the app) or a user with `platformAdmin` (granted/removed in the Edit User dialog). Checked per request in `middleware/admin.js`. You cannot demote yourself or an `ADMIN_EMAILS` admin, and the last admin cannot be removed; admins cannot be suspended or deleted until demoted.
- **Bonus minutes** - `Subscription.bonusMinutes`, extra minutes on top of the plan. `billing/usage.service.js` enforces plan minutes + bonus, but only when the plan has a monthly allowance (0 stays "no cap"). They survive a plan change.
- **Delete** - ends live calls, then removes the account; when they are the workspace's only user the workspace goes too (avatars, training jobs, knowledge, MCP servers, personas, voices, uploaded files, subscription, API keys, OAuth grants). Kept for billing and audit: the usage ledger, the workspace audit log, and conversation records without names, emails, meeting links or transcripts. Refused for yourself, for admins, and for an owner whose workspace others still use. Written to the acting admin's audit log.
- **Invitations** - `modules/invitations`: an admin invites an email onto a plan; only a SHA-256 of the link's token is stored, the link is returned once, and it expires after 7 days. The person opens `/invite/:token`, signs in with that address and accepts (`GET/POST /api/invitations/:token[/accept]`), which assigns the plan through the same `plansService.assign` an admin uses. Statuses: pending, accepted, expired (revoking expires it). The email goes through `integrations/mail`; without `RESEND_API_KEY` the admin is shown the link to share.
- **Block / unblock** - a blocked user cannot sign in, refresh, or call the API (checked per request in `middleware/workspace.js`); their refresh tokens are revoked, live calls ended, and a blocked owner's avatars stop answering share links.
- **Plans** - create, edit, delete (only when unused - the refusal says how many users are on it), mark one as the default for new sign-ups, assign one to a user. Limits (`includedMinutes`, `overageEnabled`, `concurrencyLimit`, `maxAvatars`; 0 = no limit) are read live by `billing/usage.service.js#limitsFor`, so editing a plan changes it for everyone on it and no "recalculate users" step exists. Presentation fields: `displayOrder`, `visible`, `durationType` (a label for now - minutes still renew monthly), `conditionBoxDescription`, `purchaseUrl` (http/https only), `thumbnailUrl` (uploaded through `integrations/storage`, JPG/PNG/WebP up to 5 MB; the old file is removed when replaced). **Add ready-made plans** (`plan.templates.js`) adds Free / Starter / Pro / Business; it skips keys that exist and never sets a default.
- **Monitor** - the panel's stat cards (`GET /stats`), an overview, and one user's plan, avatars and calls.

Every mutation is written to an audit log: a user's actions to their workspace's, actions with no workspace of their own (invitations, deleted accounts) to the acting admin's.

Files: `admin.service.js` (reads, block/unblock/assign), `users.service.js` (create/update/delete/export), `plans.service.js`, `admin.shared.js` (errors, audit, ending calls), `admin.mail.js` (email shell, plan-update email).
